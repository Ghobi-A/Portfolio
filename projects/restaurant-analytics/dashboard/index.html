RESTAURANT REVENUE & OPERATIONS

Executive overview

Portfolio demonstration. Mixed-status, synthetic dataset. Gross order value includes cancelled and unpaid orders; it is not audited revenue.

Metric definitions & source

Source: deterministic fictional dataset, seed 20261019, generated without reading production. Date, type and status filters intersect and apply to every measure, chart, detail table and CSV export.

Confirmed card value: payment method card AND payment status paid, as recorded by the application; settlement, live/test mode and refunds are unverified. Offline order value: all cash-on-delivery and pay-at-shop order totals, including cancelled orders. Neither is audited revenue. Unverified value = gross order value minus confirmed card value.

Cancellation rate = cancelled orders / all filtered orders. Payment failure rate = failed payment orders / all filtered orders. Card failure rate uses filtered card orders only. Menu value is quantity × listed unit price, without delivery fees or separately allocated adjustments. Pair counts deduplicate each product within an order.

Preparation = ready minus preparing, minutes. Null/negative pairs are excluded from duration statistics and retained in quality warnings. Median and P90 use linear interpolation, matching PostgreSQL PERCENTILE_CONT and DAX PERCENTILEX.INC. The 120-minute review threshold is an analyst heuristic, not an agreed service target. Durations use UTC instants; calendar grouping uses Europe/London.

Notification rates use outbox events, not orders or customer delivery guarantees. Attempts are cumulative snapshots; retries = max(attempts − 1, 0) per event. Missing records do not prove a notification was required or failed. Fee reconciliation compares totals with subtotal + delivery + the current £0.50 service-charge model; this is an assumption to revisit if pricing changes.
